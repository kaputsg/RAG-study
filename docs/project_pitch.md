# RAG-study 项目讲解稿

## 一、30 秒版

我做了一个本地知识库 RAG 问答系统。后端使用 FastAPI，前端使用 Vue，BGE 负责把文本转成 embedding，FAISS 负责向量检索，再由 DeepSeek API 根据检索资料生成回答。系统支持上传和删除 UTF-8 `.txt` 文档，也会展示 `sources` 引用来源和 `retrieval_info` 检索质量。我还补充了日志、评估脚本、索引持久化、manifest 变更检测和 Docker 后端容器化。目前它适合本地学习和演示，还不是完整 SaaS。

## 二、1 分钟版

`RAG-study` 是我独立完成的本地知识库 RAG 问答项目。用户在 Vue 页面输入问题后，FastAPI 后端会先使用 `BAAI/bge-small-zh-v1.5` 将问题转换成 embedding，再通过 FAISS 从本地知识库检索相关 chunks。检索结果经过相似度阈值过滤后，会作为 context 交给 DeepSeek API 生成回答。

除了 `answer`，接口还会返回 `sources` 和 `retrieval_info`。前端可以展示来源文件、chunk 位置、相似度，以及是否命中、最高分、来源数量和置信度。项目也支持 `.txt` 文档列表、上传和删除，文件变化后自动重建索引并刷新页面。

工程上，我增加了问答日志、基础评估脚本、FAISS 索引持久化和 manifest 变更检测，也用 Dockerfile 和 docker-compose 完成了后端容器化的初步实现。当前只支持 UTF-8 `.txt`，没有 PDF、Word、鉴权和完整线上部署，所以它定位为本地学习项目，不是完整 SaaS。

## 三、2 分钟版

我做这个项目的目标，是把 RAG 从一个概念做成可以操作、可以检查、也可以演示的完整应用。

后端使用 FastAPI，主要提供问答、文档列表、上传和删除接口；前端使用 Vue 3 和 Vite，负责问题提交、答案展示、引用来源展示和知识库文档管理。知识库目前读取本地 UTF-8 `.txt` 文件，先切分成 chunks，再使用 `BAAI/bge-small-zh-v1.5` 生成 embedding，并通过 FAISS 建立本地向量索引。

用户提问时，系统会把问题也转换成向量，通过 FAISS 找到相似片段，再用相似度阈值过滤低相关内容。命中后，RAGService 会把检索结果组合成 context，调用 DeepSeek API 生成回答。后端除了返回 `answer`，还返回 `sources`，包括来源文件、`chunk_index`、分数和原始片段；同时返回 `retrieval_info`，展示 `hit`、`max_score`、`source_count` 和 `confidence`。这样我可以判断问题出在检索还是生成，而不只是看最后一句答案。

文档管理方面，用户可以在前端上传和删除 `.txt` 文件。操作成功后，后端重建索引，前端自动刷新文档列表。为了让项目更接近真实工程，我增加了 JSONL 问答日志、接口与评估脚本、FAISS 索引持久化，以及 manifest 知识库变更检测。后端再次启动时可以优先加载已有索引；如果知识库文件发生变化，manifest 会触发重建，避免旧索引和新文档不一致。最后，我用 Dockerfile 和 docker-compose 完成了后端容器化的初步实现。

这个项目目前仍有明显边界：只支持 `.txt`，切片策略比较基础，上传和删除后采用全量重建，没有用户鉴权、增量索引和完整生产部署。后续我会优先增加 PDF/Word 解析、增量更新、混合检索与 rerank，并用更系统的评测集优化检索效果。

## 四、面试口语版

这个项目不是我直接套一个聊天页面，而是从 API 调用、文档切片、embedding、FAISS 检索一直做到前后端交互和文档管理。

简单说，它的流程是“先查资料，再让模型回答”。本地 `.txt` 文档会被切成 chunks，用 BGE 生成向量并存进 FAISS。用户提问以后，问题也会被向量化，系统检索最相关的片段，再把这些片段交给 DeepSeek API。页面上除了答案，还能看到引用来自哪个文件、哪一个 chunk、分数是多少，也能看到整体检索置信度。

后面我发现项目只做到“能问答”还不够，所以继续补了上传、删除、列表自动刷新、日志、评估脚本、索引持久化和 manifest 检测。这样服务重启时不用每次都盲目重建索引，知识库变化时又能保证索引同步。Docker 部分目前只完成后端容器化，项目也只支持 UTF-8 `.txt`，所以我会把它定位为一个完整度较高的学习项目，而不是生产级 SaaS。

## 五、技术亮点版

1. **完整 RAG 链路**：BGE embedding、FAISS 检索、相似度过滤、DeepSeek API 生成回答。
2. **可解释结果**：`sources` 展示来源文件、`chunk_index`、`score` 和原始片段。
3. **检索质量观察**：`retrieval_info` 展示 `hit`、`max_score`、`source_count`、`confidence`。
4. **前后端闭环**：FastAPI 提供接口，Vue 实现问答、文档列表、上传和删除交互。
5. **知识库一致性**：上传和删除后重建索引，manifest 检测外部文件变化。
6. **启动性能优化**：FAISS 索引和 chunks 持久化，后端重启时优先加载已有数据。
7. **工程可验证性**：JSONL 日志、接口测试脚本和基础评估问题集。
8. **部署准备**：Dockerfile 与 docker-compose 完成后端容器化初步实现。

## 六、项目不足与后续优化版

当前项目适合本地学习、答辩和小规模资料演示，但还不是生产系统：

- 只支持 UTF-8 `.txt`，不支持 PDF、Word。
- 使用固定长度 chunk，缺少按段落或语义切分。
- 文档上传和删除后仍然全量重建索引。
- 只有基础向量检索，没有关键词混合检索和 rerank。
- 评估集规模较小，还不能全面衡量召回率和答案质量。
- 没有用户鉴权、权限隔离、限流、监控和文件回滚。
- Docker 当前只覆盖后端初步容器化，没有完成前端容器、HTTPS 和正式上线流程。

后续优先级是：先支持更多文档格式与增量索引，再增加混合检索、rerank 和更完整的评估体系，最后补鉴权、监控和生产部署能力。
