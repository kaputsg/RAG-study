## 1 分钟项目导向版

我做的 RAG-study 是一个本地知识库 RAG 问答系统，定位是学习和展示完整 AI 应用开发流程。用户可以在前端上传 UTF-8 编码的 `.txt` 文档，后端会读取文档并切成 chunks，使用 `BAAI/bge-small-zh-v1.5` 生成 embedding，再用 FAISS 建立本地向量索引。

用户提问时，系统会先检索知识库中相关片段，再把这些片段作为上下文交给 DeepSeek API 生成回答。前端会展示 answer、sources 和 retrieval_info，让用户能看到答案引用了哪些文件片段、相似度如何。后续我还补充了文档列表、上传删除后自动重建索引、问答日志、基础评估问题集、FAISS 索引持久化、manifest 变更检测和 Docker 后端容器化。

这个项目让我从单纯调用 API，进一步理解了 RAG 检索链路、前后端接口设计、可解释性、可测试性和部署意识。

## 2 分钟完整介绍版

我是软件工程专业大二学生。为了系统学习 AI 应用开发，我做了一个本地知识库 RAG 问答项目，叫 RAG-study。

项目的基本目标是：用户可以把自己的 txt 学习资料放进本地知识库，然后向系统提问，系统不是直接让大模型凭空回答，而是先从本地知识库检索相关内容，再让大模型基于这些内容生成答案。

技术上，后端使用 Python 和 FastAPI，模型调用使用 DeepSeek API，中文向量模型使用 `BAAI/bge-small-zh-v1.5`，向量检索使用 FAISS。文档处理部分会读取 UTF-8 `.txt` 文件，做固定长度 chunk 切分，并保留 source 和 chunk_index。检索到相关 chunks 后，RAGService 会把它们拼成上下文，再调用 DeepSeek API 生成 answer。

前端使用 Vue 3 和 Vite，主要功能包括输入问题、提交问答、展示答案、展示 sources、展示 retrieval_info、上传文档、查看文档列表和删除文档。上传或删除文档后，后端会重建索引，前端会自动刷新列表。

在工程化方面，我还做了环境变量管理、异常处理、JSONL 问答日志、基础评估问题集、FAISS 索引持久化、manifest 知识库变更检测，以及 Dockerfile 和 docker-compose 的后端容器化初步实现。

这个项目目前不是正式产品，也没有多用户权限、数据库后台或 PDF/Word 全格式支持。它更像是我从 API 调用到 RAG 检索、后端接口、前端页面、测试评估和部署准备的一次完整练习。我的主要收获是理解了 AI 应用不是只调模型，还要关注检索质量、回答依据、系统边界和可维护性。

## 面试官追问后的补充版

如果面试官继续追问，我会补充三点：

第一，项目不是简单调用 DeepSeek API。它有完整的 RAG 链路，包括文档读取、chunk 切分、embedding、FAISS 检索、相似度阈值过滤、上下文拼接和模型生成。

第二，我在项目里特意做了可解释性展示。前端不仅显示 answer，还显示 sources 和 retrieval_info。这样可以看到答案来自哪些文件片段、检索分数如何，方便判断回答是否可信。

第三，我知道项目边界。当前只支持 UTF-8 `.txt`，索引更新还是全量重建，也没有多用户权限和正式部署能力。后续我会优先优化文档格式、chunk 策略、rerank、增量索引和评估体系。

## 适合老师验收/答辩的自我介绍

老师好，我的项目是 RAG-study，一个基于本地知识库的 RAG 问答系统。项目目标是把大模型问答和本地资料检索结合起来，让系统可以围绕指定 txt 文档回答问题，并展示回答依据。

项目后端使用 FastAPI，前端使用 Vue。核心流程是：读取本地 `.txt` 文档，切分成 chunks，使用 BGE 中文向量模型生成 embedding，通过 FAISS 建立索引；用户提问后，系统检索相关片段，再调用 DeepSeek API 生成回答。前端展示答案、引用来源和检索信息。

除了基础问答，我还实现了文档上传、文档列表、文档删除、上传删除后重建索引、问答日志、评估问题集、索引持久化、manifest 变更检测和后端 Docker 化初步实现。当前项目主要用于本地学习和演示，只支持 UTF-8 `.txt` 文档。后续可以继续扩展更多文件格式、优化检索质量和完善部署能力。
