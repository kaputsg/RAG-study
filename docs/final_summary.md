# RAG-study Day 1-Day 20 最终项目总结

## 1. 项目为什么做

RAG-study 的起点是想把“大模型 API 调用”扩展成一个真正可以运行和展示的 AI 应用项目。单纯调用模型只能回答通用问题，不能稳定回答本地资料中的内容。通过这个项目，我希望理解 RAG 的基本链路，并练习后端接口、前端交互、文档管理、日志评估、持久化和部署准备。

这个项目的定位是学习型本地知识库 RAG 原型，不是正式上线产品。

## 2. 项目最终做成了什么

最终完成的是一个基于 FastAPI、Vue、BGE、FAISS 和 DeepSeek API 的本地知识库 RAG 问答系统。

当前项目可以：

- 读取本地 UTF-8 `.txt` 知识库文档。
- 将文档切分为 chunks。
- 使用 BGE 生成中文文本向量。
- 使用 FAISS 做向量检索。
- 调用 DeepSeek API 基于检索上下文生成回答。
- 通过 FastAPI 提供问答和文档管理接口。
- 通过 Vue 前端完成提问、回答展示、来源展示和文档管理。
- 展示 `sources` 和 `retrieval_info`。
- 支持文档上传、删除和索引重建。
- 支持问答日志、基础评估、索引持久化和 manifest 变更检测。
- 提供 Docker 后端容器化初步实现。
- 整理演示、验收、简历、面试、作品集和复盘文档。

3. 本地 `.txt` 文档读取和 chunk 切分。
4. BGE 中文 Embedding 模型。
5. FAISS 向量索引和相似度检索。

9. `sources` 与 `retrieval_info` 的可解释展示。
10. FAISS 索引持久化与 manifest 知识库变更检测。

## 7. 项目中遇到的问题

- 直接调用大模型无法回答本地资料问题。
- 文档太长时，整篇传给模型不现实。
- chunk 切分会影响召回质量。
- 检索结果不一定足够相关。
- 用户需要知道回答来自哪里。
- 上传或删除文档后，索引可能和文件系统不同步。
- 后端重启时重复构建索引会影响启动效率。
- 持久化索引可能加载到旧数据。
- 前后端联调需要处理 loading、error 和状态刷新。
- 项目展示时容易夸大能力边界。

## 8. 问题是如何解决的

- 用 RAG 流程解决本地资料问答问题。
- 用 chunk 切分降低单次上下文长度。
- 用 BGE 和 FAISS 完成语义检索。
- 用相似度阈值和 `retrieval_info` 辅助判断检索质量。
- 用 `sources` 展示答案引用来源。
- 在上传和删除后重建索引，并刷新前端文档列表。
- 用 FAISS 索引持久化减少重复构建。
- 用 manifest 检测知识库是否变化。
- 在前端展示加载状态、错误信息和结果区域。
- 在 README 和 docs 中明确说明当前只支持 txt、本地运行、未正式上线。

- 能从 0 到 1 完成一个 AI 应用项目。
- 理解 RAG 的基本链路。
- 能用 FastAPI 封装后端接口。
- 能用 Vue 做基础前端交互。
- 能处理文档上传、删除和索引重建。
- 有日志、评估、持久化、Docker 等工程化意识。
- 能进行项目复盘和面试表达。
- 能区分已经实现的能力和后续规划，保持项目表达真实。

## 10. 当前项目不足

- 目前只支持 UTF-8 `.txt` 文档。
- 暂不支持 PDF / Word。
- chunk 切分仍比较基础。
- 没有 rerank 重排序。
- 没有流式输出。
- 没有多轮对话历史。
- 没有数据库保存问答记录。
- 没有用户登录和权限系统。
- 没有正式部署到云服务器。
- 评估问题集还比较基础。

## 11. 如果重新做一次，我会怎么优化

- 更早规划模块边界，让文档加载、索引、检索和生成职责更清晰。
- 更早加入评估问题集，避免只凭主观感受判断 RAG 效果。
- 更早记录检索结果和失败案例，方便后续调参。
- 在前端一开始就规划好文档管理区域和问答区域。
- 把 README、演示文档和面试表达分阶段整理，而不是最后集中整理。
- 在加入新功能前先写清楚当前边界，避免项目无节制膨胀。

## 13. 一段适合写进学习总结的话

通过 RAG-study，我从单纯调用大模型 API 出发，逐步完成了一个本地知识库 RAG 问答系统的完整原型。这个过程覆盖了文档处理、向量化、检索、上下文生成、后端接口、前端展示、日志评估、索引持久化、Docker 容器化和项目文档整理。它让我认识到 AI 应用开发不只是调用模型，还需要关注数据、检索质量、可解释性、可测试性、部署准备和真实的能力边界。

## 14. 一段适合发社交平台的短版复盘

最近完成了 RAG-study v1.0 的第一阶段收尾。

这是一个本地知识库 RAG 问答项目，技术栈包括 FastAPI、Vue、BGE、FAISS 和 DeepSeek API。项目支持 txt 文档知识库、向量检索、基于知识库回答、引用来源展示、检索质量展示、文档上传/删除、索引重建、日志评估、索引持久化、manifest 变更检测和后端 Docker 容器化。

这次最大的收获是：AI 应用不只是调 API。要做成一个可演示的项目，还需要处理文档、检索、接口、前端、日志、评估、部署准备和项目表达。当前版本仍是本地学习原型，只支持 txt，后续第二阶段会继续扩展文档格式、检索质量和交互体验。
